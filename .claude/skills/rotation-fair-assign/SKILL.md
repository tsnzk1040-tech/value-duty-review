# ローテ公平アサイン（POC）

## 本質

**テーマを回すこと**がローテの本体。営業日数そのものにこだわらない。  
日付はテーマ枠に対して、土日祝を避けて乗せるだけ。

## 重要要件（トシオ）

0. **前回のローテ必須** — 無いと生成しない。貼り付け登録、またはノート用コピーで今回分が次の「前回」になる
1. **土日祝を避ける**（日本の祝日は生成年を見て自動）
2. **あまり近しい日付に同じ人が来ない**（間隔目安＝クールダウン）
3. **前回と同じ Value 帯にならない**（ラベル先頭の Value番号：1〜6）
4. **最後は常塚（ツネヅカ＝トシオ）** → 次のローテ設計を回せる
5. **開始テーマ**は前サイクル最終の次（自動）。**違う場合だけ**手動修正
6. サイクル内テーマはカタログ順固定（日別テーマ編集なし）
7. ノート用は `1-①` のみ全文、他はコードのみ
8. 休み番なし（枠＝アクティブ人数）。新人は初回のみ後方

## 生成の流れ

1. 開始テーマを解決（自動／手動）
2. **テーマ枠**（既定＝アクティブ人数。休み番なし。テーマ列はカタログを巡回し不足分はラップ）
3. 同じ枠数だけ、**サイクル開始日**（既定＝いま決まっているローテ最終のつぎ営業日）から土日祝を避けて日付を置く
4. 当番を振る  
   - 最終枠は常塚固定（それ以外に出さない）  
   - **新人は追加された初回ローテのみ後方**（最終当番の直前）。ノート用コピー後は通常扱い（手動チェックなし）  
   - 全員1回（0回は想定外）  
   - 前回 Value 帯が異なる人を優先  
   - 日付間隔ペナルティ
5. 手直しは当番のみ

生成結果には **前回との間隔**を出す（サイクル最終→開始、および当番ごとの前回当番からの営業日数）。

## PoC デフォルト日付

- 開始日 **自動**: `resolveCycleStart`＝**いま決まっているローテ（前回履歴）最終日のつぎ営業日**（シャッフルしても同じ）。履歴が無いときだけ今日のつぎ営業日
- 枠数は設定に出さない（＝アクティブ人数）
- 実表の 2026-07-29 は履歴サンプル用のみ
