# ローテ公平アサイン（POC）

## 本質

**テーマを回すこと**がローテの本体。営業日数そのものにこだわらない。  
日付はテーマ枠に対して、土日祝を避けて乗せるだけ。

## 重要要件（トシオ）

0. **前回のローテ必須** — 無いと生成しない。既定シード、またはノート用コピーで今回分が次の「前回」になる
1. **土日祝を避ける**（日本の祝日は生成年を見て自動）
2. **あまり近しい日付に同じ人が来ない**（間隔目安＝クールダウン下限）
2b. **開きすぎない**（間隔上限のソフト目安。設定可・0で無効）
3. **前回と同じ Value 帯にならない**（1〜6。原則ハード。候補切れ・最終当番ロック時のみ例外。設定でOFF可）
4. **最後は常塚（ツネヅカ＝トシオ）** → 次のローテ設計を回せる
5. **開始テーマ**は前サイクル最終の次（自動）。**違う場合だけ**手動修正
6. サイクル内テーマはカタログ順固定（日別テーマ編集なし）
7. ノート用テーマ列は **すべてコードのみ**（`1-①` も全文にしない）。日別行に **前回間隔**（`N営業日`＝前回当番日からの営業日数）を付ける
8. 休み番なし（枠＝アクティブ人数）。新人は初回のみ後方

## 生成の流れ

1. 開始テーマを解決（自動／手動）
2. **テーマ枠**（既定＝アクティブ人数。休み番なし。テーマ列はカタログを巡回し不足分はラップ）
3. 同じ枠数だけ、**サイクル開始日**（既定＝いま決まっているローテ最終のつぎ営業日）から土日祝を避けて日付を置く
4. 当番を振る  
   - 最終枠は常塚固定（それ以外に出さない）  
   - **新人は追加された初回ローテのみ後方**（最終当番の直前）。ノート用コピー後は通常扱い（手動チェックなし）  
   - 全員1回（0回は想定外）  
   - 前回 Value 帯が異なる人を優先  
   - 日付間隔ペナルティ
5. 手直しは当番のみ

生成結果の日別・ノート貼付に **前回との間隔**を出す（サイクル最終→開始は警告、当番ごとは各行の「N営業日」）。長い「当番ごとの前回間隔: …」警告は出さない（折り返しで空きが多く見えるため）。

## PoC デフォルト履歴・日付

- **前回履歴の最新**＝トシオ提供の「新ローテーション」（`POC_HISTORY_CYCLES` / `data/local/members-and-rotation.json` と同当番）。設定版 `SETTINGS_VERSION` 更新で再読込
- 担当は実表どおり。**テーマ列は実表に無い**ため、カタログ先頭から日順割当（19でラップ）。実テーマが分かれば差し替え
- 開始日 **自動**: `resolveCycleStart`＝いま決まっているローテ最終のつぎ営業日（履歴なし時のみ今日のつぎ）
- 枠数は設定に出さない（＝アクティブ人数）
