# メンバー投稿へのレビュー — 構成ルール（SSoT）

実運用ログ（例: 2026-08 抽出）から確定した **返信の並び**。  
味・合格感は [output-taste.md](output-taste.md)。プロセス全体は卒業制作 `DECISIONS.md` §2a。

## 並び（必須順）

| 順 | ブロック | 必須 | 内容 |
|----|----------|------|------|
| 1 | お礼 | 必須 | `{呼び名}さん、振り返りコメント共有頂きありがとうございます！` |
| 2 | 要約共有 | 必須 | Value帯＋何番目＋**投稿の要点**＋`想いを共有頂きました！` |
| 3 | 所感・着想 | 必須 | 共感 → 同テーマ前回（[same-theme-quote.md](same-theme-quote.md)）→ 効く理由付きの組織への「こうしたら？」1点（検索して調べた結果を織る。『調べた要点』は書かない） |
| 4 | 参考リンク | 任意 | `♯短いタイトル`＋改行＋URL。無い日も可 |
| 5 | 締めの呼びかけ | 必須 | 奨励・考える余白。所感の提案は復唱しない |

## 要約と所感の役割分担（主旨）

| ブロック | 役割 |
|----------|------|
| **要約共有** | **リーダーの理解を共有する体裁**で、投稿者が今日 **理念浸透リレーを実践した事実**（調べる・取り入れる等）をメンバーに見える化する。評価・実感の言語化はしない |
| **所感・着想** | 上司として寄り添う距離感で、今日の具体＋検索して調べた結果を織った組織への「こうしたら？」。布教せず、参照に引きずられない |

要約本文に「一歩前進した」「浸透が進んだ」等を直書きしない。実感・提案は所感側（ただし標語押しにしない）。

### 所感の型

1. 投稿への共感・感謝（ですね可・カジュアル）
2. 同テーマ前回の履歴があるときは、条件を満たすときだけアプリが固定文を入れる。文型・出典・bridge／intro・意味閉じは **[same-theme-quote.md](same-theme-quote.md)** が正（所感・今日の所感からの転用禁止。無理なら差し込まない）
3. 今日のテーマに会話の延長で一言（訓示にしない）
4. メンバー全体への「こうしたら？」**1点**（今日の具体＋検索して調べた結果を織る。効く理由の半文。個人の明日TODO禁止。『調べた要点』『要点メモ』は本文に出さない）

## 要約共有の型（形式）

```
Value{N}　{Value名}   の{何番目}番目の行動指針について、{投稿の言い換え}想いを共有頂きました！
```

### 定型のあと（厳守）

- **対象の行動指針ラベル／全文は書かない**（`1-②「できない」より…` など）
- **Value帯名の再掲もしない**（定型先頭に一度だけ出る）
- `{投稿の言い換え}` は **リーダー理解としての言い換え**（メンバーの実践事実が伝わること）。評価語・実感フレーズは置かない
- **お礼・「本日／今日の振り返り」定型は書かない**（お礼ブロックの仕事）
- **理解を深める行為**（調べる・意味を広げる等）と **自分に取り入れる実践** があれば必ず触れる（リレー実践の事実）
- アプリ実装: Gemini はあいだの文だけ生成 → `assembleSummary` で枠を付与

## 締めの呼びかけ

- 必須の一文。所感の提案を繰り返さず、奨励・考える余白で閉じる
- 空の『皆さんと一緒に〜』固定にしない。本線は `POST /api/review/draft` `kind=closing`
- 案のプロンプト正本は `src/lib/review/closing.ts`。静的リストは退避のみ
- 『明日試してみませんか』級は所感の「こうしたら？」側。締めには書かない

## レビュー本文に入れない

- チャットUIメタ（既読・時刻・「詳細」など）
- 運用メモ単体（投稿時間ルール、当番スイッチ）※必要ならレビューと分けて送る
- メンバー投稿末尾の「次回テーマ／担当」（相手の文の一部。要約に引きずらない）
- 実装・POC・スキル名などのメタ発言

## 調べる関門（所感の前）

調べるは **Googleで参照URLを1本持ってくる** まで。要点・フォーカスは所感ステップ。

1. **検索ワード候補〜3つ**（Gemini）→ 選ぶか、希望ワードを手入力
2. **Google AIモードで調べる**（`udm=50` を別タブで開く）
3. OKな結果を **共有→企業理念リレー**（PWA Share Target）。Google URLを優先して **参照1本に差し替え**（手のURL＋コメント欄は無し）
4. **所感へ**（コピー済みのページ本文を貼って要点まで）。材料が無い／URLだけならエラー。Androidでクリップボードを直接読めないときは所感の欄を長押しして貼る（貼ると要点メモ）。狙いを書いて所感下書き

## アプリ組み立てとの関係

- **コメント対象営業日**: 下書きで入力（既定＝今日JST以前の直近営業日）。`投稿用にコピー／共有` 時にこの端末の履歴へ保存
- **履歴**: 正本はこの端末の localStorage（キーは変えない。起動時は既存LSを読む）。履歴確認は読むだけ。保存時は各テーマ最大2件（保険）。**6-④（カタログ末尾）を保存したとき**当該周の1-①〜6-④を残し、前回周を外す。手動JSON退避UIは置かない
- **今日の行動指針**: 投稿本文の `4-③` / `4-3` 等から自動セット（Selectで修正可）。`matchValueItemFromSourcePost`
- **定型のあと**: 行動指針コード／「行動指針3-②について」等の再掲は書かない（`extractSummaryBody`／`repairDuplicatedGuidelinePhrase` で機械除去）
- お礼: `formatThanks`（`src/lib/review/thanks.ts`）
- 要約: `POST /api/review/draft` `kind=summary`（Gemini＝あっさり／こってり 2案。定型枠は共通。投稿に無いことは足さない）
- 要約直し: 同 API `kind=summary-revise`（**直し専用プロンプト**。初回の120〜180字は載せない。厚く＝同じ事実の言い足しで約1.2倍・投稿に無いことは足さない。簡潔なら約0.8倍）
- 観点 `lens`: **要約を厚くする**（所感には渡さない）
- 要点: 同 API `kind=research-brief`（所感ステップ。貼付で自動。採用した要約モデル）
- 検索ワード候補: 同 API `kind=keyword-suggestions`
- 所感: 同 API `kind=leader`（参照・要点・フォーカス必須。同テーマ前回は [same-theme-quote.md](same-theme-quote.md)）
- 参照リンク: PWA共有で調べるへ（♯＝検索ワード）
- 組み立て: `formatReviewPost`（お礼→要約→所感→任意♯リンク→締め。**ブロック間は空行**）。通読で `assembledPost` として最終編集可。定型の二重は要約組み立て時に機械修正
- **PWA共有**: GET `/share-target?title=&text=`（`url` は置かない）。**投稿定型（振り返りコメント／想いを共有／指針コード）があるときだけ①本文**。それ以外（Google結果・記事URL付き含む）は調べるの参照。URLが無ければ検索ワードから AIモード URL を組み立てる。

- **投稿前**: 通読ステップの最終チェック（`src/lib/review/final-check.ts`）／Cursor は [final-check.md](final-check.md)
- プロンプト: `src/lib/review/prompts.ts`
