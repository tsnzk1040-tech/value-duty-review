# 同テーマ前回の引用（SSoT）

所感②のアプリ固定文。構成の並びは [structure.md](structure.md)。味は [output-taste.md](output-taste.md)。

## 目的

同テーマの**前回レビュー要約**に残った実践事実を一言で見せ、「〇〇さんもこう見えていた」とリレーする。  
前回の所感（共感・提案）を引くと浸透の主旨から外れる。

## 文型

```
同テーマ前回の{呼び名}さんの要約では、「{一言}」{末尾}
```

- 『前回の〇〇さん』だけの言い方は禁止（前日と誤解される）
- 『要約では』は**出典制約**（ラベル飾りではない）

## 層（混線させない）

| 層 | 役割 | やること |
|----|------|----------|
| **① 候補の箱** | どこから取ってよいか | **前回要約のあいだのみ** |
| **② 箱の中の選び方** | どの一文を主線にするか | **bridge → intro → 差し込まない** |
| **③ 仕上げ** | 読める一言にする | **意味閉じ**（字数スライスで切らない） |

## ① 出典（厳守）

**取る**

- 前回レビューの要約定型の**あいだ**（実践事実の言い換え）
- 保存済み `summary` を優先
- `summary` が空／所感混入なら、履歴の投稿全文から切り出し:  
  **「…について、」の直後〜「（想いを）共有頂(だ)きました」の直前**

**取らない**

- 前回の所感・締め・お礼
- 本人投稿の生切り
- 今日の所感下書きからの転用・コピー
- 共感口調（分かります／いいですね／ありがとう 等）
- 企業理念テーマ文言だけの再掲

取れなければ**差し込まない**（所感に逃げない）。

## ② 選び方

1. **bridge（優先）** … 今日の主線（今日の要約・投稿の実践）と自然につながる一言 ＋ 意味閉じ  
   → 末尾は通じる／重なる／つながる系
2. **intro（フォールバック）** … 正直につなげられない／前回が的を射ていないとき。指針・Valueの核に乗る一言を**単なる紹介** ＋ 意味閉じ  
   → 末尾は触れていました／実践がありました系（通じる系は使わない）
3. どちらも無理 → **差し込まない**

## ③ 意味閉じ

- 完結した実践の一言（読んだだけで通る）
- 途中切れ（しかし／なので／て、 で終わる等）禁止
- 記号末尾ヒューリスティックに頼らず、選定時に閉じる

## UI

所感欄の上にステータスを出す。

- 引用あり（保存済み要約／全文から切り出し）
- 引用なし＋理由（履歴なし／切り出し失敗／bridge・intro不可 等）

サーバが意図的に外したあと、クライアントが生シードを再差し込みしない。
